6. THE CHAT SYSTEM
==================================================

The chat is the AI assistant inside the admin environment.
It is powered by OpenAI through backend code.

The public website no longer exposes the admin chat UI.
That is intentional.
The chat is now treated as an admin-only tool.

How chat works at a high level:

1. The Android app sends a prompt.
2. The backend or worker prepares the request.
3. The backend/worker builds a system prompt and a structured JSON payload.
4. That request is sent to the OpenAI Responses API.
5. The result comes back as structured data.
6. The app displays the summary and any returned issues/actions.

There are two transport modes now:

- websocket
- http

What websocket mode means:

The app connects to `/ws/chat`.
The server streams tokens back piece by piece.
This makes the chat feel more live.

What http mode means:

The app sends a normal POST request to `/api/v1/chat/ask`.
The response comes back as a normal request/response instead of a live stream.

This was recently made real in the Android app.
Before, transport mode was not a real end-to-end control.
Now the app actually switches behavior based on the selected transport setting.

8. WHAT "TONE", "REASONING", AND "VERBOSITY" MEAN HERE
==================================================

These can be confusing, so here is the plain-English version.

Tone:

Tone is not a native OpenAI API field in this implementation.
So it is handled by system-prompt instructions.

That means:

- direct = blunt and plain
- calm = steadier and softer
- technical = more engineering-focused
- executive = more concise and decision-focused
- creative = more expansive and idea-friendly

Reasoning:

Reasoning controls how much internal reasoning effort the model is allowed to use when the Responses API supports it.
This is sent as reasoning effort in the OpenAI request body.

Verbosity:

Verbosity controls how brief or detailed the model should be in the actual output.
This is now sent in the OpenAI request body when using Responses mode.

11. HOW THE ANDROID APP, WEBSITE, AND CHAT WORK TOGETHER
==================================================

This is the most important section.

The easiest way to understand the system is this:

The website is public.
The Android app is private.
The chat is a private admin assistant that talks to the same backend/control surface used by the website.

The actual flow looks like this:

Public website flow:
- a user visits the site
- Cloudflare serves the website assets
- the worker handles public routes and site APIs
- the user sees branding, products, catalog, and downloads

Admin app flow:
- you open the Android admin app
- the app talks to the same base domain/API
- the app authenticates as admin
- the app can run admin endpoints, upload files, run commands, and control chat settings

Chat flow:
- the app sends a prompt
- the backend/worker builds the OpenAI request
- the backend/worker sends it to OpenAI
- the result comes back to the app
- webhook/logging/state update can happen after the response

In other words:

The website and the app are two different front doors into the same larger system.
The difference is that the public website should stay limited and safe, while the admin app is the high-power control interface.
